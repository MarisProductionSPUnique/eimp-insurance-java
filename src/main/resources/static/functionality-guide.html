IBS Banking — Customer portal

Oracle XE training environment. Implemented: authentication and read-only accounts.

LoginAccountsRefreshServicesLogoutSupport

1. Customer login

Enter assigned username and private password, click Login. Expected: customer dashboard and account cards. No self-registration or reset control. POST /api/login reads IBS_USER_APP.V_IBS_LOGIN.

L1: verify assigned access and error message. L2: investigate 401, 429, 503 and request logs. L3: review authentication and session logic.

2. Dashboard and account details

View welcome name, account number, available balance, currency, customer number, account type, branch, IFSC, status and opened date. No eligible accounts may appear. No edit or debit operation. GET /api/accounts reads IBS_APP.V_IBS_CUSTOMER_ACCOUNT.

L1: capture masked evidence. L2: check API response, request ID, customer eligibility and authorized read-only SQL. L3: investigate view joins and Java mapping.

3. Refresh accounts

Click Refresh accounts. Expected: Accounts refreshed and current account details. No balance modification. On failure cards clear; 401 returns to login. L2: investigate latency and stale or duplicate results.

4. Banking services — pending

Beneficiaries, Fund transfer and Transaction history are Coming soon tiles, not operational navigation. No financial writes are available.

5. Logout

Click Logout. POST /api/logout ends the session, hides account cards and returns to login. Expected: Logged out. L1: verify screen; L2: investigate errors; L3: review session invalidation.

6. Troubleshooting and practice

401: verify access or session expiry. 429: stop repeated attempts and allow rate limit recovery. 503: check application health, request logs and approved Oracle connectivity checks. Missing account: verify eligibility and view results. Record timestamp, impact, HTTP status, request ID and recovery evidence. Escalate defects to L3; never collect passwords or perform unauthorized restarts.

Monitor · Log analyzer

Practice: login, record masked account fields, refresh, logout and verify login screen. Interview: How do you troubleshoot missing balance? How do 401 and 503 differ? How do you correlate request IDs?
